# Direct worker artifact/audit substrate

Status: pilot substrate. This is a Direct Workbench ledger. It neither reads nor writes WorldManager canonical stores and it has no project-truth authority.

## Law and boundary

The trusted harness pins an artifact-class policy digest and actor/role/purpose bindings before opening the store. It issues opaque declaration, action, administrative-read, and evidence-registration principals; copied JSON and a role claimed inside a proposed policy have no authority. Evidence registration is pinned only to the adapter named by a separate evidence-receipt authority. A declaration principal is checked against the harness binding independently of the proposed policy. The resulting policy is rebuilt, recursively frozen, and revalidated whenever it crosses a persistence or routing boundary.

The policy keeps `read`, `propose`, `challenge`, `admit`, and `subscribe` rights independent, names eligible producer and auditor roles, states producer/auditor separation requirements, and designates the sole admission role. Routing performs deterministic bipartite matching: each required audit must have a different auditor, and every advertised producer must have a complete feasible audit assignment that observes required producer separation. An impossible policy is rejected at declaration. Starting an audit binds the deterministic witness assignment into the authenticated `audit_started` event; every verdict must match its exact requirement/actor/role entry, and restart replay recomputes that witness. This prevents a locally eligible first verdict from consuming an identity needed by another requirement. A plan does not launch a provider.

Each instance follows this typed lifecycle:

`requested -> under_production -> candidate -> under_audit -> supported | requires_revision | contradicted -> admitted | rejected | remanded`

A remanded artifact advances to a new revision only when production restarts. Every audit is bound to the exact project, workthread, artifact class, artifact, revision, policy digest, requirement, actor, and registered evidence record. Evidence cannot be introduced through caller-chosen JSON: the service-owned evidence authority first issues an opaque receipt over the canonical record, and the store accepts that receipt only with the exact pinned adapter principal. Copied receipts, producer/auditor registration principals, and a different adapter fail closed. Source capture, session, turn, and canonical-envelope digest are persisted, then lifecycle calls resolve the returned ID/digest pointer from the registry. A new revision has a fresh audit set. A workspace-worker terminal record is evidence for `candidate_recorded`; it is never evidence of admission and never changes project truth.

Workers do not actively message or request the parent. Candidate and verdict facts are append-only ledger transitions. A parent must hold both `read` and `subscribe`, create an immutable subscription, and poll a bounded safe projection. Parent-visible head inspection additionally requires that exact subscription and actor; generic `read` cannot bypass it. A narrowly separate `admin_read` principal permits only the declared manager role to inspect a head without a subscription. Projections contain typed transition metadata and exact evidence references only; they contain no prompts, paths, provider payloads, transcripts, commands, artifact bodies, actors, or bound audit assignments.

## Persistence and concurrency

`createDirectArtifactAuditStore` derives a dedicated SQLite path from an absolute root and bounded store identity. It accepts neither a database handle nor an arbitrary database filename. Every existing root/store/database path component is checked with `lstat`, both root and store directory are canonicalized, and containment is proved before SQLite opens; symlink redirection fails before a database is created. The constructor also requires an explicit key-file path. The key must be a non-symlink regular file containing at least 32 bytes and, on POSIX, owned by the process user with no group/world permissions. New database files are set to owner-only access, while an existing permissive database is rejected rather than silently modified. Only the key fingerprint enters store identity; key bytes never enter SQLite. Borrowed/foreign schemas, unexpected tables (including WorldManager tables), mismatched path/store/key/authority identity, and altered schema definitions are rejected. The handle, MAC key, and every mutation helper are JavaScript-private.

The database uses WAL, foreign keys, full synchronous durability, and store-owned immediate transactions. An unexpected outer or reentrant transaction is rejected instead of returning success for work another caller can roll back. Policy declarations, registered evidence, events, audit verdicts, and subscriptions are append-only. Events form one sequence-contiguous digest chain from a store-specific genesis digest. Store custody, declarations, evidence registrations, complete event/input envelopes, and subscriptions also carry HMAC-SHA-256 tags under the external key. Consequently, a writer who can coherently recompute public digests but cannot read the protected key cannot rewrite history successfully. The mutable artifact head is a projection updated by exact revision/state/version compare-and-swap in the same transaction as its authenticated event. Idempotency is scoped by actor, operation, and key; it persists a safe canonical input envelope and its digest, and reuse with different input is rejected.

Every open runs SQLite integrity and foreign-key checks, authenticates store custody and every replay-critical immutable row with the external key, revalidates canonical policy/evidence/event JSON and row bindings, checks the event chain, recomputes bound audit assignments, replays authorization and lifecycle history, reconstructs all audit sets and heads, and compares those projections with persisted rows. Missing, replaced, permissive, or wrong key custody and any foreign, incomplete, or unauthenticated store fail closed.

The store rejects unissued or copied principals and evidence receipts, unknown or forged actor/role pairs, missing rights, policy digest substitution, unregistered or cross-scope evidence, non-adapter evidence registration, stale heads, verdicts outside the bound assignment, duplicate requirement verdicts, reuse of one auditor identity within a revision, forbidden self-audit, and incomplete admission. Admission requires a complete `supported` audit set plus an explicit `admitted` decision from the designated role. Raw-shaped keys and path-like values are rejected recursively at both API ingress and final event construction.

## Integration seams

The substrate deliberately does not connect to the native agent pool, workspace backend, provider runtime, `src/main.js`, or WorldManager. A later integration must keep the evidence-receipt authority and its `register_evidence` principal inside a trusted adapter, resolve a durable workspace-worker terminal/lifecycle receipt, and issue the canonical `workspace_worker_terminal` receipt only after exact session, turn, workspace-binding digest, policy digest, artifact scope, cancellation acknowledgement, and settlement state agree. The recommended cross-store order is durable terminal capture, idempotent sealed evidence registration, candidate CAS, then cleanup eligibility; retries use the same receipt/evidence identity. No worker receives the authority, actively messages an upstream agent, or promotes a candidate to project truth. A separate, explicitly authorized bridge would be required for any canonical WorldManager admission.
