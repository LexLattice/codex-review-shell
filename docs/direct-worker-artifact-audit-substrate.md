# Direct worker artifact/audit substrate

Status: pilot substrate with a bounded workspace-worker adapter. This is a Direct Workbench ledger. It neither reads nor writes WorldManager canonical stores and it has no project-truth authority.

## Law and boundary

The trusted harness pins an artifact-class policy digest and actor/role/purpose bindings before opening the store. It issues opaque declaration, action, administrative-read, and evidence-registration principals; copied JSON and a role claimed inside a proposed policy have no authority. Evidence registration is pinned only to the adapter named by a separate evidence-receipt authority. A declaration principal is checked against the harness binding independently of the proposed policy. The resulting policy is rebuilt, recursively frozen, and revalidated whenever it crosses a persistence or routing boundary.

The policy keeps `read`, `propose`, `challenge`, `admit`, and `subscribe` rights independent, names eligible producer and auditor roles, states producer/auditor separation requirements, and designates the sole admission role. Routing performs deterministic bipartite matching: each required audit must have a different auditor, and every advertised producer must have a complete feasible audit assignment that observes required producer separation. An impossible policy is rejected at declaration. Starting an audit binds the deterministic witness assignment into the authenticated `audit_started` event; every verdict must match its exact requirement/actor/role entry, and restart replay recomputes that witness. This prevents a locally eligible first verdict from consuming an identity needed by another requirement. The routing plan itself does not launch a provider; the bounded adapter described below consumes one exact plan.

Each instance follows this typed lifecycle:

`requested -> under_production -> candidate -> under_audit -> supported | requires_revision | contradicted -> admitted | rejected | remanded`

A remanded artifact advances to a new revision only when production restarts. Every audit is bound to the exact project, workthread, artifact class, artifact, revision, policy digest, requirement, actor, and registered evidence record. Evidence cannot be introduced through caller-chosen JSON: the service-owned evidence authority first issues an opaque receipt over the canonical record, and the store accepts that receipt only with the exact pinned adapter principal. Copied receipts, producer/auditor registration principals, and a different adapter fail closed. Source capture, session, turn, and canonical-envelope digest are persisted, then lifecycle calls resolve the returned ID/digest pointer from the registry. A new revision has a fresh audit set. A workspace-worker terminal record is evidence for `candidate_recorded`; it is never evidence of admission and never changes project truth.

Workers do not actively message or request the parent. Candidate and verdict facts are append-only ledger transitions. A parent must hold both `read` and `subscribe`, create an immutable subscription, and poll a bounded safe projection. Parent-visible head inspection additionally requires that exact subscription and actor; generic `read` cannot bypass it. A narrowly separate `admin_read` principal permits only the declared manager role to inspect a head without a subscription. Projections contain typed transition metadata and exact evidence references only; they contain no prompts, paths, provider payloads, transcripts, commands, artifact bodies, actors, or bound audit assignments.

## Persistence and concurrency

`createDirectArtifactAuditStore` derives a dedicated SQLite path from an absolute root and bounded store identity. It accepts neither a database handle nor an arbitrary database filename. Every existing root/store/database path component is checked with `lstat`, both root and store directory are canonicalized, and containment is proved before SQLite opens; symlink redirection fails before a database is created. The constructor also requires an explicit key-file path. The key must be a non-symlink regular file containing at least 32 bytes and, on POSIX, owned by the process user with no group/world permissions. New database files are set to owner-only access, while an existing permissive database is rejected rather than silently modified. Only the key fingerprint enters store identity; key bytes never enter SQLite. Borrowed/foreign schemas, unexpected tables (including WorldManager tables), mismatched path/store/key/authority identity, and altered schema definitions are rejected. The handle, MAC key, and every mutation helper are JavaScript-private.

The database uses WAL, foreign keys, full synchronous durability, and store-owned immediate transactions. An unexpected outer or reentrant transaction is rejected instead of returning success for work another caller can roll back. Policy declarations, registered evidence, events, audit verdicts, and subscriptions are append-only. Events form one sequence-contiguous digest chain from a store-specific genesis digest. Store custody, declarations, evidence registrations, complete event/input envelopes, and subscriptions also carry HMAC-SHA-256 tags under the external key. Consequently, a writer who can coherently recompute public digests but cannot read the protected key cannot rewrite history successfully. The mutable artifact head is a projection updated by exact revision/state/version compare-and-swap in the same transaction as its authenticated event. Its identity includes project, artifact class, workthread, and artifact ID; audit-set keys and replay projections carry the same class boundary, so equal artifact IDs in different declared classes remain independent. Idempotency is scoped by actor, operation, and key; it persists a safe canonical input envelope and its digest, and reuse with different input is rejected.

Every open runs SQLite integrity and foreign-key checks, authenticates store custody and every replay-critical immutable row with the external key, revalidates canonical policy/evidence/event JSON and row bindings, checks the event chain, recomputes bound audit assignments, replays authorization and lifecycle history, reconstructs all audit sets and heads, and compares those projections with persisted rows. Missing, replaced, permissive, or wrong key custody and any foreign, incomplete, or unauthenticated store fail closed.

The store rejects unissued or copied principals and evidence receipts, unknown or forged actor/role pairs, missing rights, policy digest substitution, unregistered or cross-scope evidence, non-adapter evidence registration, stale heads, verdicts outside the bound assignment, duplicate requirement verdicts, reuse of one auditor identity within a revision, forbidden self-audit, and incomplete admission. Admission requires a complete `supported` audit set plus an explicit `admitted` decision from the designated role. Raw-shaped keys and path-like values are rejected recursively at both API ingress and final event construction.

## Integration seams

`workspace-worker-artifact-adapter.js` is the first callable live bridge to the actual `DirectNativeAgentPool` and `WorkspaceWorkerLifecycleRegistry`; it is not installed as an automatic `src/main.js` controller. A trusted parent supplies a pre-existing producer child ID and service-owned role principals and auditor launch profiles. The adapter rejects artifact, candidate, admission, verdict, evidence, and audit-assignment fields anywhere in a provider launch envelope. Workers receive only the ordinary workspace-worker project/workthread, delegation packet, tool profile, and task message. They receive no ledger principal, evidence authority, artifact scope, revision, requirement, verdict, or admission ability.

Before recording a candidate, the adapter requires a completed isolated-worktree pool record, a complete terminal epistemic capture, matching project/workthread and binding digests, no unacknowledged cancellation, and a durable lifecycle state of `completed / released / quiescent`. It then asks the registry for a typed settlement receipt whose current session and final `session_completed` event agree. A cancellation-unacknowledged, settlement-blocked, incomplete-capture, wrong-scope, or receipt-mismatch path stops before evidence registration and candidate creation. The service issues the evidence receipt with the exact pinned adapter principal. Its evidence ID is derived from the settlement receipt, so the same terminal settlement cannot be relabeled for another artifact lineage in the store.

The successful order is terminal capture and lifecycle settlement receipt, passive parent subscription creation, service-sealed evidence registration, candidate CAS, authenticated binding of the deterministic audit assignment, provider dispatch for each assigned service profile, sealed audit evidence, assigned-role verdict events, and a bounded subscription poll. The current pilot treats successful complete terminal capture under each trusted service profile as the configured profile verdict; providers do not choose or transmit verdicts. It deliberately never calls admission or cleanup, never writes project or WorldManager canonical state, never sends a worker-to-parent message, and retains every worktree for inspection. An auditor launch or capture failure after `audit_started` leaves the artifact truthfully `under_audit` with the missing verdict rather than fabricating completion.

There is no cross-database transaction between the lifecycle registry and authenticated artifact store. A crash after evidence registration but before candidate CAS can leave an authenticated unreferenced evidence row; deterministic evidence identity makes the same binding retry-safe. A crash after assignment binding can leave an inspectable incomplete audit and presently requires an operator/service retry plan with fresh child IDs. The lifecycle settlement receipt checks the registry's public digest and row/event consistency but is not independently MAC-authenticated; filesystem custody of the lifecycle database remains part of the trusted substrate. Automatic producer assignment, restart orchestration for partially dispatched audits, generalized verdict interpretation, cleanup eligibility, and any canonical admission bridge remain intentionally unwired.
